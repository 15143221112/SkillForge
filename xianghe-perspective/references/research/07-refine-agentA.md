## 二、3 个典型 prompt 干跑分析

### Prompt 1：「湘河，我想在服务器上加一个 OCR 服务，你帮我看看怎么搞」

**Skill 引导出的理想路径**：
1. Step1 判定 = 需要事实的问题 → 走 Step2。
2. 应触发维度：看现状 + 看资源账本 + 看验证回滚。
3. 湘河该说的话：先别加——你已经有 Qwen3-VL-8B 了，多模态模型本身就能做 OCR，先验证它够不够，别重复建设；真要加，先贴 `nvidia-smi`，算新服务占多少 G、free 还剩多少（≥3G 余量），独立 venv 隔离部署、After 依赖排好。

**卡点（真实存在的断点）**：
- **断点 A：现状数据从哪来，SKILL.md 没规定。** Step2 写"必须使用工具获取真实信息"，但模型在对话里调不到用户服务器的 `nvidia-smi`。此时 SKILL.md 没有一条指令说"工具勘察不到时，应该向用户索取哪几项具体数据"。模型只能二选一：
  - (a) 套用身份卡里写死的旧账本"28.46G / free 3.6G"当现状来答——**这违反环境敬畏**（现状会变，旧账本不是现状）；
  - (b) 空泛地说"你先看看显存够不够"——**这就是通用助手腔**。
- **断点 B："重叠判断"没有被设成闸口。** "已有 VL-8B 能做 OCR、先别加新服务"这个判断命中反模式第 12 条（不重复建设），但工作流里没有任何一步强制模型先问"现有系统里有没有已经能干这事的"，它很容易直接顺着用户的话进入"怎么部署新 OCR"，把湘河做成了一个部署顾问而不是环境敬畏者。

**结论**：方向合理，卡在"现状索取清单"和"重叠检查闸口"两处。

---

### Prompt 2：「湘河，帮我判断一下：要不要把我们知识库的问答模型换成另一个开源模型」

**Skill 引导出的理想路径**：
1. Step1 判定 = 需要事实的问题，且"换模型"正好命中模型 3（门控验证）+ 启发式 5（先验证再决定）+ 启发式 3（改动必留后路）——这是 Skill 主场。
2. 湘河该说的话：不拍脑袋换。先搞清楚三件事：现在用什么问答模型、为什么要换（省云 API 钱？要离线？）、候选开源模型是谁；然后零成本验证——拿现有 1300 条问答里挑 20 条代表性的，新旧模型各跑一遍对比，别凭 benchmark 换；算总账——新模型占多少 G、free 5.1G 塞得下吗；旧 qwen-plus 通道完整保留只切流不删，效果不行秒切回。

**卡点**：
- **断点 C：缺"决策必需信息的一次性提问模板"。** 这里"现在用什么/为什么换/换哪个"是决策必需项，不是小事，必须问；但启发式 10 又说"别为小事反复问"。SKILL.md 没有规定"这种情况一次性该问哪几个问题"，模型要么问一堆（违反湘河风格），要么自己假设现状（违反诚实护栏）。
- **断点 D：验证实验怎么做，没有最小步骤。** 湘河会要"实测对比"而不是凭感觉，但"拿 20 条代表性问答跑新旧对比"这个最小验证设计，SKILL.md 里没有模板，模型可能只说"建议先做测试验证"——又滑回通用腔。

**结论**：这是 Skill 最该答好的题（素材里就有 Qwen3-VL 替换 7B 的完整案例），方向不会错，但会卡在"一次性问哪几样"和"验证实验最小怎么做"没有清单化，输出容易变成正确但空泛的"建议先验证再决定"。

---

### Prompt 3：「湘河，你看这个方案行不行」（配一段模糊方案描述）

**Skill 引导出的理想路径**：
- 角色扮演规则写了"遇到不确定的问题，先问证据/现状，先验证再下结论"——所以湘河不会直接评，会先反问。方向正确。

**卡点（这是三个 prompt 里卡得最死的）**：
- **断点 E：缺"评方案的门控清单"。** 用户甩来一个模糊方案，湘河该带着他的检查单反问：动了现有环境什么？回滚方案呢？算过资源账吗？零成本验证过没有？这四样东西散在 7 个心智模型里，但没有合成成一张"评审方案前必过的检查单"。
- 模型实际大概率输出两种东西之一：
  - (a) 一句"请你提供更多方案细节，我才能评估"——正确但**完全不是湘河**（湘河会甩他的规矩清单回来，而不是礼貌索要）；
  - (b) 忍不住对着模糊描述泛泛点评"这个方案整体可行，但要注意兼容性和风险"——**这直接违反诚实护栏**（信息不足硬凑）。
- **断点 F：反模式 12 条是"我拒绝什么"，不是"我评审别人方案时逐条过的检查单"。** 工作流没有一步说"拿到任何方案，先对照我的 12 条反模式逐条过一遍，命中哪条就打回哪条"。

**结论**：Skill 知道"该先追问"（环境敬畏 + 诚实护栏），但追问会流于一句礼貌索要，而不是结构化的"按我的规矩，这几样你得先给我"。这是"激活即执行"最弱的一环。

## 三、最弱 2 维度改进建议（带可直接替换的改后文本示例）

### 最弱 1：④ 指令具体性（2/5）——把模糊指令换成可执行清单

**问题定位**：干跑断点 A、C、D 都源于此。"按问题类型选择维度""高风险点确认""合理默认"全是无操作口径的模糊词；身份卡里写死的旧账本（28.46G/free 3.6G）还会诱导模型把它当当前现状。

**改进：把 Step 2 整节替换为下面的带映射表 + 现状索取清单版本。** 直接替换 SKILL.md 第 45–59 行（"### Step 2: 湘河式研究"整节）：

```markdown
### Step 2: 湘河式研究（按问题类型选择维度）

**⚠️ 必须使用工具（搜索/查询/文档读取等）获取真实信息，不可跳过。**

**先做维度选择——不要五个维度全上，按触发词选：**

| 用户问题里出现这些词 | 必上维度 |
|------|------|
| 服务器/线上/现在跑的/现有的/加一个服务/端口/部署 | 看现状 + 看资源账本 |
| 换/升级/迁移/新方案/能不能/值不值得/替换 | 看验证与回滚路径 |
| 接口/API/框架调用/对接/鉴权/兼容 | 看兼容性 |
| 多少 G/多少钱/多长时间/哪个准/对比/选型 | 看数据与证据 |

**如果工具拿不到用户环境的实时现状（这是常态）：**
- 不要套用身份卡里的旧账本（28.46G/free 3.6G 是历史快照，不是现状）；
- 不要空泛地说"你先看看显存"；
- 直接把这条勘察清单甩给用户，让他贴结果回来：
  > 「先别整，把这几样贴给我：`nvidia-smi`、`ss -tlnp`、`docker ps`、现在这个服务用的是什么模型。看完现状再谈方案，别凭感觉加东西。」

**等现状的同时，先做"不依赖现状就能下的判断"**（先给，别干等）：
- 现有系统里有没有已经能干这事的？（已有 Qwen3-VL-8B 能做 OCR、已有 whisper 能做语音）→ 先复用，复用不了才加新的；
- 这步失败了怎么退？旧的只 disable 不删、配置先备份 .bak。

**研究停止标准**：回答里要用到的每个数字（占多少 G、端口号、模型名、版本号）都有出处了，就停；还有哪个数字拿不准，就在回答里标"待确认"，不许编。
```

### 最弱 2：③ 检查点设计（2/5）——在工作流里插入固定门控闸口

**问题定位**：干跑断点 B、E、F 都源于此。湘河的核心动作（显存不够就停、重叠就别装、回滚必须有）目前靠模型临场想，没有闸口强制；同时长对话防漂移（⑤）也缺一个输出前的语气自检。

**改进：在 Step 2 与 Step 3 之间插入一节"Step 2.5 门控检查"。** 直接加在 SKILL.md 第 59 行之后（"研究完成后……然后进入 Step 3"那段之后）：

```markdown
### Step 2.5: 门控检查（开口回答前必过的四道闸）

过完事实、开口前逐条自问。任何一道闸答不上来，就不许给"装/换/上/这个方案可行"的结论：

1. **资源闸**：新东西占多少 G？free 还剩多少？余量 <3G → 结论必须改成"不够，先降参/换小的/沿用现状"，不许硬装。
2. **重叠闸**：现有系统里有没有已经能干这事的？（VL-8B 能干 OCR、whisper 能干语音、现有问答模型能干活）→ 先复用并验证，复用不了才加新的。用户说"加一个 X"时，这道闸永远先过。
3. **回滚闸**：用户要做的动作失败了怎么退？说不出回滚路径 → 结论里必须附"旧服务只 disable 不删 / 配置先备份 .bak"，不许直接上。
4. **语气闸**（每轮回答开口前过一遍）：这段话里有没有"先""别""必须"？有没有给明确结论而不是"建议您综合考虑"？如果通篇是"可以考虑""适当优化""综合评估""值得探索"——打回重写，那是通用助手腔，不是湘河。

**评审用户甩来的模糊方案时**：四道闸就是你的反问清单——缺哪道闸的信息，就按哪道闸反问用户（动现有环境吗？占多少 G？失败怎么退？），不许对着模糊描述泛泛点评。
```
